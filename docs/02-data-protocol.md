# 数据整理、质量核对与划分协议

> 状态：拟采用的研究协议，尚不代表数据已经下载或核验。文中数量来自数据集论文，实际纳入数量以审计记录为准。正式训练前冻结本协议、病例清单和划分文件；之后的改动必须记录理由。

## 1. 数据是什么，模型要画出什么

采用 BrEaST（TCIA 集合名 Breast-Lesions-USG）。数据集论文报告 256 名患者、256 张超声图像，包括 154 例良性、98 例恶性和 4 例正常图像。图像、专家标注和病例表共同构成研究数据，不能只下载图片后按文件名猜测配对关系。

本课题的目标是**病例表指定的肿瘤／目标病灶区域**。这里“肿瘤”不等于恶性癌症：良性目标也需要分割。模型学习“是否属于目标区域”，不输出良恶性诊断。诊断类别仅用于患者划分和探索性分组。

原始标注区分 tumor masks 与 other masks。other masks 不并入训练目标。它们可能对应其他异常或结构，在本研究的二元目标中归入目标以外区域；这不表示它们在医学上一定健康。论文必须交代这一目标范围，避免把结果解释为“检测图像中的全部异常”。

主分析拟纳入 252 例有目标病灶的病例。4 例正常图像保留为独立的误检探索集，不参与训练、阈值选择或主分割指标平均。数量变化需用纳入流程说明；缺失掩码绝不能自动当作正常。

## 2. 下载与原始数据保全

1. 从 [TCIA 官方入口](https://www.cancerimagingarchive.net/collection/breast-lesions-usg/)进入实际下载源，保存下载日期、来源地址、版本或文件名、引用要求及许可说明。
2. 原始压缩包、图像、掩码和病例表按下载内容保存到本地 `data/raw/`，保持原始内容不变。文件组织规则先依据实际下载结构确认。
3. 为原始压缩包及解压文件计算 SHA-256，保存校验清单。哈希用于识别内容变化及完全重复，不证明标注医学正确。
4. 将处理结果写入 `data/processed/`，人工核对记录写入 `data/audit/`。任何修复均保留原文件和变更理由。
5. 原始图像、病例明细、模型权重及预测文件不直接上传公开 GitHub。仓库保存程序、协议、字段说明和可公开的汇总；数据的后续共享须遵守原来源许可。正式引用数据，不因“公开可下载”就省略引用。

## 3. 先建立病例清单，再读取模型输入

以“一行一个患者／一张图像”为主表粒度；本集合是否确实一人一图仍需核对。路径存相对于项目根目录的位置，避免泄露本机账户路径。下面只定义字段，不提供虚构病例行。

| 字段 | 含义与规则 |
|---|---|
| `patient_id`, `image_id` | 来自正式病例标识；不能用重新排序后的行号替代关联键 |
| `image_path`, `image_sha256` | 原始图像位置和内容校验值 |
| `tumor_mask_paths`, `other_mask_paths` | 两类标注分别记录，允许列表，禁止混装 |
| `diagnosis_group` | 按数据字典映射的良性、恶性、正常；保留原始值 |
| `margin_raw`, `margin_labels` | 原始 Margin 内容和按字典解析后的标签 |
| `pixel_size_raw` | 原表 Pixel_size 值、单位说明和缺失状态 |
| `width`, `height`, `channels`, `dtype` | 原始图像形状、通道与数据类型 |
| `target_pixels`, `target_area_ratio` | 原始目标像素数，以及除以原图像素总数后的比例 |
| `has_target`, `audit_status`, `exclusion_reason` | 目标状态、核对状态和明确排除原因 |
| `duplicate_group`, `split` | 重复／相关图像标记和最终集合归属 |

多条 tumor mask 是否属于同一目标的分块，必须先查数据字典和对应关系。只有确认它们都属于本课题目标时，才取逐像素并集；不能看到多个文件就全部求并集。若标注表示多个不同对象，先写清楚目标定义再编码。

## 4. 数据审计清单与处理原则

对全部病例做自动核对，人工浏览标注叠加图；建议为全部 256 张图生成联系表，逐例确认明显错配、异常尺寸和标注问题。

| 核对项 | 通过条件或后续处理 |
|---|---|
| 病例关联 | 表中图像、掩码能唯一找到；孤立文件、重复键、缺文件均输出清单 |
| 图像完整性 | 可解码；尺寸为正；数值有限；记录灰度／RGB／RGBA与取值范围 |
| 掩码完整性 | 与原图宽高一致；检查唯一像素值和通道；不能未经确认就按“非零即目标”处理颜色标注 |
| 透明通道 | 检查 alpha 是否全不透明；透明部分不能静默当黑背景或按颜色算目标 |
| 目标存在性 | 有病灶病例的原始目标非空；正常病例需由病例表确认，而非由缺失文件推断 |
| 重复与相关性 | 文件哈希找完全重复；感知相似仅作人工复查线索，不自动删除 |
| 可见标记 | 记录图像内文字、测量线、箭头等，讨论模型依赖这些线索的风险 |
| 缩放结果 | 最近邻缩放后掩码仍二值且目标未消失；异常病例暂停进入训练并形成处理记录 |

如果发现跨患者标识的重复图像，应先调查标识和来源；确认属于相关图像时保持在同一集合中，必要时按重复组划分并尽量保持诊断比例。该情况会偏离初始“一患者一图”假设，须报告实际处理过程。禁止让同一患者或重复图像同时出现在训练与测试中。

RGB 图像先检查三个通道是否相同。纯灰度存储可直接读单通道；含彩色标记的图像需确认转换影响，再统一按明确的灰度转换公式处理。原始字节和审计图保留，不用随意裁掉文字的方法掩盖来源差异。

## 5. 固定患者划分与防止信息泄漏

主数据按患者划分为约 60% 训练、20% 验证、20% 测试，划分种子固定为 `20261013`。在良性与恶性类别内分层，尽量维持各集合类别比例。初始实现可以先分出 40%，再将该部分等分；若最终为 252 个有效独立病例，常见取整结果为 151／50／51，具体以固定实现导出的名单为准。

保存 `patient_id, split, diagnosis_group` 等必要字段、所用程序版本及划分文件哈希。四种方案和三个训练种子共用同一划分；训练随机种子不会重新洗牌患者归属。正常病例单独标记 `normal_exploration`。

- 训练集用于参数学习、病灶相对大小分组阈值等规则的估计。
- 验证集用于早停、少量超参数选择和概率阈值选择。
- 测试集在方案冻结后统一评估，不依据测试成绩增加训练次数或修改处理规则。

查看测试图进行尺寸和配对审计属于数据质量核对，不能据此挑选增强策略或筛除模型难以分割的病例。增强只在训练集加载时进行；不能先扩增图片再随机划分。

## 6. 固定预处理与同步增强

主方案直接将原图缩放至 `256×256`。图像使用双线性插值，掩码使用最近邻插值，输出 `float32` 图像和取值为 0／1 的目标。确认原图为 8 位强度后将图像除以 255；若原始位深不同，先定义固定映射，不照搬该除数。主方案不使用由测试数据估计的均值或标准差，不加入直方图均衡、滤波等额外因素。

直接缩放可能改变宽高比，记录原始宽高比及水平、垂直缩放倍率，并在局限中说明。不得按真实病灶位置裁剪模型输入，这会在推理时泄露答案。若目标缩放后消失，先暂停并审查该病例和处理方案，不偷偷补画目标、改插值或在单个方案中排除它。

增强组对每张训练图以 0.5 的概率应用一次仿射变换：旋转角度均匀取自 ±10°，水平、垂直位移独立取自图像宽高的 ±5%。同一次变换的角度和位移同时作用于图像与掩码；图像双线性、掩码最近邻，越界填充值均为 0。主实验不使用垂直翻转、弹性形变、随机裁剪或额外颜色增强。

检查增强后的掩码是否为空或明显被截断。若变换导致目标完全消失，该次变换回退为原样并记录次数；此规则四组实现中保持固定，不修改病例归属。验证和测试仅做确定性预处理。保留少量增强前后叠加图，用来检查同步性。

## 7. 数据阶段验收

进入正式训练前，应能回答：实际纳入多少人、排除谁及原因、每例读入哪个目标、正常与缺失如何区分、三个集合是否交叉、缩放后标签是否正确。验收材料包括审计汇总、纳入流程、病例清单、固定划分、预处理配置及可视化核对记录。

原始文件、病例表和处理结果未实际核验前，不填写“已通过”、不生成虚构的样本分布或审计结论。
