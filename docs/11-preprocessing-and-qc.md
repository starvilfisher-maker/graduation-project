# 确定性预处理与第二轮数据核对

日期：2026年10月14日。本文记录实际执行的读取、缩放和技术核对；未生成患者划分，未运行模型，未冻结最终纳入清单。第一轮发现与原始来源见[历史记录](10-data-first-pass.md)。

## 本步解决什么问题

超声图像是模型的输入，专家掩码是监督学习的参考答案。掩码中的1表示本研究指定的目标病灶，0表示目标以外区域；后者不等于医学上一定健康。模型随后要学习逐像素的目标概率，现在尚未产生预测。

下载的全部522个PNG均采用RGBA编码，其中A是透明度。直接删除A通道可能把原本不可见的颜色暴露给模型；直接把A当作掩码又可能改变部分透明的边界像素。第一轮保守审计因此阻止了自动放行。本步根据实际编码建立明确读取规则，并检查规则是否正确保留原图与标签的对应关系。

## 已实现的读取规则

代码位于 `src/breast_unet/preprocessing.py`，规则文件为[preprocessing_v1.json](../configs/preprocessing_v1.json)，规则标识为 `breast_v1`。程序与规则文件一致性纳入测试。规则已实现，完整实验协议仍待冻结。

| 对象 | 实际规则 | 为什么这样做 |
| --- | --- | --- |
| 源图像 | 验证PNG、uint8及L/RGB/RGBA模式，其他模式拒绝 | 不把未知位深套入0—255规则 |
| 图像透明度 | RGBA按alpha/255在黑色背景合成 | 全透明处不暴露隐藏RGB；部分透明处按实际透明度显示 |
| 灰度与归一化 | 加权灰度后取值为0—1，保留float32 | 统一单通道输入；不用全数据估计均值或标准差 |
| 图像缩放 | Pillow浮点双线性插值，直接缩放至256×256 | 保留连续图像强度；所有方案共用相同处理 |
| 掩码颜色 | RGB三通道必须相同，颜色值仅允许0/255；白色为1 | 标签表示区域归属，不是光学亮度 |
| 掩码透明度 | 白色且alpha为0时报告冲突；部分透明白色仍为1 | 不把alpha作为软标签或用透明度阈值删去原有前景 |
| 掩码缩放 | Pillow最近邻插值，输出0/1 | 不产生无意义的分数类别 |
| 目标存在性 | 原始非空且缩放后仍非空 | 目标消失须停止核对，不能改称正常或静默删除 |

RGBA像素的具体公式为：

```text
I = (alpha / 255) × (0.299 R + 0.587 G + 0.114 B) / 255
```

RGB图像相当于alpha为255；L模式按灰度/255处理。部分透明白色掩码中发现的两个特殊像素仍保留为前景，原始标签不被改写。

`prepare_image(image_path)`只接受图像路径，返回 `(256,256,1)` 的float32输入；真实掩码不会参与图像裁剪、亮度调整或其他推理输入的构造。`prepare_target(mask_path)`仅用于有目标病例，空目标会报错。正常病例未来的数据加载方式应单独实现，不能把缺文件转成正常标签。

本步没有实施增强、去噪、均衡化、重新标注或图像裁剪。原始文件保持不变。直接缩放会改变非正方形原图的宽高比；病例清单已记录原始宽高比及水平、垂直缩放倍数，论文需说明这一限制。

这是**助手对技术显示的检查**，不是256幅大图的逐幅精细审阅，也不是用户或导师的人工确认，更不是临床医生重新评价标注。缩略图不能排除细微边界误差。具体查看文件、哈希、范围和发现单独保存在本地 `assistant_visual_review_v1.json`；原始生成清单没有被改写成“已人工完成”。

图册还用64×64灰度图的Pearson相关系数≥0.985且平均绝对像素差≤0.05筛查近似图线索，本次候选对为0。该筛查不能证明不存在所有近似或同患者图像，也不据此合并或剔除记录。患者身份仍依据官方一人一图说明和CaseID关联。

图册的 `small_review` 筛选只是展示目标像素数小于600的复查图，不能当成论文的“小病灶”分组。正式相对大小分组仍需仅用训练集真值确定切点，详见[统计方案](03-experiment-and-statistics.md)。

## 如何核对图册

先看含other的示例，理解黄色与青色的目标区别；再看“自动提示”、较小目标和正常病例；随后浏览全部总览，对疑似错位的图打开大图。核对重点是文件配对、轮廓位置、缩放后是否保留目标，不要求应用统计学学生自行判断良恶性或修改医生边界。

每个需要解释的病例保留“看到什么、依据是什么、保留或排除理由、谁复核”的记录。没有真实复核者时不填写人工通过。对医学边界本身的疑问交给导师讨论，不能把肉眼觉得难分割当成删除依据。正式患者划分前，应完成复核记录与最终纳入清单。

## 可运行入口及证据保全

基础检查仍不安装模型依赖。审计与图册需要NumPy、Pillow和openpyxl，可在项目独立环境安装审计依赖：

```bash
python3 -m pip install -e '.[audit]'
python3 scripts/audit_breast.py --decoding-policy breast_v1 --raw-dir data/raw/BrEaST-v1 --output-dir data/audit/my_decoded_run
python3 scripts/build_data_review.py --audit-dir data/audit/my_decoded_run --output-dir reports/my_data_review
```

每次重新运行使用新目录。省略 `--decoding-policy` 时仍使用首轮保守的 `strict` 规则，会报告本集合尚未放行的透明度/颜色项；这保留历史行为，不是推荐的当前解码方式。

审计记录实际执行的读取规则、代码哈希、输入/输出文件哈希及运行库版本。图册生成前复核审计、代码、规则和原图哈希；发生变化应重新审计并使用新输出目录。生成图册本身不会填写人工审阅结论。

本地验证为37项测试全部通过。新增测试覆盖透明RGB隐藏、部分透明合成、灰度权重、部分透明白色标签、冲突标签、非二值/彩色掩码、错误位深、确定性图像输入、坐标对齐、空/消失目标与完整审计小样本。全量真实数据检查与这些合成边界测试是两种不同证据。

本次实际运行版本为Python 3.12.14、NumPy 2.3.5、Pillow 12.3.0、openpyxl 3.1.5。它们是本次数据检查环境，尚非正式TensorFlow训练环境。图册528个本地图片/链接引用已检查存在，无缺失；本地浏览器实测“自动提示”“正常病例”“有other标注”分别显示1、4、7例，图像正常加载。所有图像和病例记录保留本地，公开仓库仅同步程序、规则与汇总文档。

## 目前可写入论文的“数据预处理”文字

以下文字描述已执行的方法，适用于方法章节草稿；最终提交时应与冻结协议核对：

> 本研究对BrEaST数据集的原始图像、目标病灶标注及其他结构标注分别建立文件清单，并检查文件关联、图像尺寸、通道编码、标签取值及重复内容。针对RGBA图像，首先依据alpha通道将图像合成至黑色背景，再按0.299R＋0.587G＋0.114B进行灰度转换，并以255归一化至0—1范围。目标掩码经验证RGB通道一致且仅包含0与255后，以白色像素定义前景；部分透明白色像素仍保留为前景，不将透明度作为连续标签。图像采用双线性插值，掩码采用最近邻插值，直接缩放至256×256。预处理不依赖真实病灶位置裁剪图像，不估计全体数据的归一化统计量。程序检查了缩放后目标的非空性，并生成原始显示、专家标注轮廓与缩放结果的对照图供进一步复核。其他结构标注不并入本研究目标。

可在数据质量说明中据实报告“256张原图和266张标注均完成解码及缩放检查，252个目标掩码缩放后均非空”。尚不能写“全部病例经人工核验”“已完成数据划分”“模型分割精度达到……”或“方法具有临床诊断价值”。

本步之后先完成复核记录和样本纳入，再实施固定患者划分；随后进入训练环境、数据管道和U-Net的小规模运行验证。
