# 模型训练、对照实验与统计分析协议

> 状态：正式实验前拟冻结的默认方案，不是已完成的实验结果。先用训练与验证数据完成流程调试，再固定配置；测试集仅在协议冻结后用于最终评价。本文不承诺任何方案一定更优。

## 1. 研究问题与四组对照

主要问题是：在相同患者划分、网络结构和训练预算下，损失函数与数据增强如何影响目标病灶的分割质量？这是方法比较研究，不能从单一小样本数据集推导临床诊断或部署效果。

| 方案 | 损失函数 | 训练增强 | 用途 |
|---|---|---|---|
| A | BCE | 无 | 基线 |
| B | 0.5 BCE＋0.5 Dice loss | 无 | 单独考察联合损失 |
| C | BCE | 有 | 单独考察增强 |
| D | 0.5 BCE＋0.5 Dice loss | 有 | 考察组合策略 |

每组训练种子固定为 `17, 42, 2026`，合计 12 次正式训练。预设主要比较为 **D−A**；B−A、C−A、D−C、D−B为次要比较。D−A代表组合策略差异，不能将其全部归因于增强或损失中的某一个因素。必要时探索交互差异 `(D−C)−(B−A)`，样本小，谨慎解释。

## 2. 网络结构与输入输出

采用 TensorFlow／Keras 二维 U-Net，输入形状 `256×256×1`，输出 `256×256×1` 的病灶概率。编码器通道依次为 32、64、128、256，每层包含两次 `3×3, padding="same"` 卷积及 ReLU，再以 `2×2` 最大池化下采样。瓶颈通道 512，同样采用两次卷积。

解码器逐层用 `2×2` 转置卷积上采样，与对应编码器特征按通道拼接，再做两次卷积，通道依次为 256、128、64、32。最后用 `1×1` 卷积和 sigmoid 输出概率。主比较不添加预训练、注意力、Batch Normalization 或 Dropout，以控制额外变量。

首次运行应保存网络摘要并核对：输出尺寸与掩码一致；概率在 0—1；输入、损失及梯度有限；一个很小的训练子集可以被明显拟合。该小样本调试仅排查程序问题，不能作为最终性能。

## 3. 损失、训练与早停

令第 i 个像素的标注为 `y_i∈{0,1}`，预测概率为 `p_i`。BCE 先在每张图的像素上取平均，再在批次上取平均；采用框架的稳定计算实现。对每张图定义：

\[
S(y,p)=\frac{2\sum_i y_i p_i}{\sum_i y_i+\sum_i p_i+\epsilon},\quad \epsilon=10^{-7},\qquad L_{Dice}=1-S(y,p).
\]

联合损失为 `0.5×BCE＋0.5×L_Dice`，Dice 部分也先逐图计算再平均，避免把整个批次展平成一张图。分子不添加平滑常数。主训练数据有非空目标；意外空标注应由数据审计拦截，不依赖平滑常数掩盖异常。

| 项目 | 拟冻结值 |
|---|---|
| 优化器、初始学习率 | Adam，`1e-3`；主比较不另加学习率调度 |
| 批量大小、训练上限 | batch size 8，最多 100 epochs |
| 早停监控 | 验证集逐病例 soft Dice 的宏平均，越大越好 |
| 早停参数 | patience 15，min_delta `1e-4`，恢复最佳权重 |
| 检查点 | 保存与早停同一“改善”判据下的最佳权重 |
| 训练随机性 | 同时设置 Python、NumPy、TensorFlow 随机种子 |
| 数值精度 | 主比较 float32；改变精度需重新固定所有方案 |

共同监控 soft Dice，避免 BCE 组和联合损失组因为监控不同量而获得不公平的停止规则。指标应累计每例得分与病例数，不简单平均大小不同的批次均值。不同实验可能早停于不同轮数，这属于固定规则的结果；应记录实际轮数、最佳轮次和用时。

M5 MacBook Air 24GB 可先承担数据处理和试跑。TensorFlow 与 Metal 的兼容性和训练速度须实测，不能只凭芯片型号保证加速。记录系统、Python、TensorFlow、加速插件及设备；若 batch 8 无法运行，先统一降低批量、更新协议，再重新开始四组正式比较。不同方案不能因显存问题各用不同预算。尽量启用确定性计算，并如实记录硬件算子仍可能存在的非确定性。

## 4. 验证集确定二值化阈值

每个“方案×种子”训练完成后，使用其最佳权重预测验证集。从 `0.10, 0.15, …, 0.90` 的17个候选阈值中选择逐病例宏平均 Dice 最大者，判定规则统一为 `p≥t`。并列时先选最接近 0.50 的阈值；仍并列取较大者。保存完整候选得分和最终阈值。

正式测试使用各自验证集选出的阈值，不在测试集搜索。作为辅助结果，可以同时报告固定阈值0.50下的成绩，帮助判断差异是否主要来自阈值选择；这不能替代预设主分析。主方案不做“只保留最大连通区域”、孔洞填充等后处理。以后若增加，必须作为独立且由验证集确定的探索实验。

验证集既用于早停又用于阈值选择会带来一定选择偏差，因此调参保持克制并如实报告。方案比较过程中不反复查看测试成绩；结果揭晓后想到的新实验应标为后续探索。

## 5. 测试指标与空掩码规则

主指标在统一的 **256×256 网格**上逐病例计算。设预测二值区域为 P，真实区域为 G，交集像素数为 TP，预测多出的像素为 FP，漏掉的像素为 FN：

\[
Dice=\frac{2TP}{2TP+FP+FN},\qquad IoU=\frac{TP}{TP+FP+FN}.
\]

Dice 为主要指标，IoU 为辅助指标；它们相关，不能视为两项独立的重复证据。可补充像素级召回率 `TP/(TP+FN)`、精确率 `TP/(TP+FP)`，解释漏分与多分；不将大量背景像素产生的高准确率作为主要成绩。

- 真实目标非空、预测为空：Dice、IoU、召回率均为0；精确率因分母为0记 NaN，明确有效例数。
- 真实与预测均为空：Dice、IoU 记 NaN，不人为计1后混入主平均。
- 真实为空、预测非空：Dice、IoU可记0作原始记录，但正常图仍不混入主分割平均。
- 对每张正常图，报告预测阳性像素数、占全图比例，以及是否存在任何阳性像素。只有4例，应逐例展示，不声称已可靠估计临床特异度。

正常图使用各模型在有病灶验证集上选定的阈值；不能根据这4张图再调阈值。“任何阳性像素即误检”的规则很严格，应解释其含义。如另设小连通域过滤标准，要提前定义并单列结果。

NaN表示指标未定义：Python可用`None`、JSON用`null`、CSV用空值保存，不要为了让表格完整而改成0或1。汇总时报告排除空值后的有效病例数；主分析有目标病例若出现空真值，应停止并回查数据处理。

轮廓可将二值预测用最近邻插值映射回原图显示，标明“评估在256网格、原图仅用于展示”。不得将原分辨率指标与256网格指标混在同一列比较。

## 6. 汇总：病例差异与训练波动分开写

每个模型先对测试病例逐例算分，再报告病例均值、标准差、中位数、四分位距、最小值和有效例数。**病例标准差**描述容易和困难病例之间的差异。

每种方案另列3个种子的测试集平均 Dice，再报告这3个均值的平均值、标准差和范围。**种子标准差**反映固定划分下训练随机性的波动；只有3次重复，不宜据此拟合精细的波动分布。

同一患者的3次预测不构成3位新患者，像素也不构成独立患者。两种标准差不相互替代；如果写“均值±标准差”，表头必须说明标准差的来源。两类标准差均采用样本标准差（分母为对应观测数减1），并同时列出观测数。

## 7. 配对差异与置信区间

所有方案在同一批测试患者上评价，因此采用患者配对比较。对方案 g、病例 j、种子 s 的 Dice 记为 `d_gjs`，先对三个种子平均，得 `d̄_gj`。主要比较的病例差为 `Δ_j=d̄_Dj−d̄_Aj`，效应量为所有测试病例 `Δ_j` 的均值；以Dice分值报告，也可乘100转换为百分点。

配对 Bootstrap 的固定实现：

1. 从 N 个测试患者标识中有放回抽取 N 个，保留同一患者全部方案与种子的结果。
2. 在抽中患者上计算平均配对差异。
3. 重复5000次，随机种子 `20261013`；取2.5%和97.5%分位数形成95%百分位置信区间。
4. 使用同样的患者重采样索引计算各个预设次要比较，报告方向、大小和区间。

该区间描述**给定数据划分、已训练模型和既定阈值时的测试患者抽样不确定性**。它不包含重新划分数据、重新调参、无限次重新训练以及跨医院分布变化的不确定性。固定划分上的3次训练不能代表3次独立外部验证。

不以“p＜0.05”作为论文成立的条件。次要比较较多，应标为探索性，不能只挑显著项讨论。如果以后加入正式多重假设检验，需预设检验方法与校正规则。无差异或负向结果仍可说明某种策略在本数据上的局限。

## 8. 大小、边缘与失败病例分析

病灶相对大小定义为原始目标面积除以原图总面积。用**训练集**这一比例的三分位数确定小／中／大分组阈值，再原样应用于测试集，公布阈值和各组例数。若两个阈值重合或分组极度失衡，不强行切组，改为连续散点图与描述性分析，并记录处理。

面积占比代表图像中的相对占用，受视野和缩放影响，不等于实际肿瘤尺寸。数据表中的 Pixel_size 只有在单位、方向、适用图像、缺失情况均确认后，才可用于单独的物理面积探索；不能凭字段名自动换算毫米。

Margin 按原始数据字典解析，可能为多标签。按标签分别统计时同一病例可以进入多组，须注明组间非互斥及每组例数。边缘标签不能直接当成图像模糊程度，也不由非医学专业研究者凭肉眼补造“边界模糊”标签。样本很少的组只作个案展示。

分析需同时呈现：各组Dice分布、漏分与过分情况、大小与得分关系，以及边缘相关案例。小目标的少量边界误差会造成较大的Dice下降，不能简单解释为模型完全没有识别目标。

展示病例采取预设规则，例如按三个种子平均Dice选择最好、中位附近、最差病例，另加小目标失败例与过分明显例；若重叠则不重复。原图、专家轮廓、预测轮廓、病例编号、方案、种子或汇总规则、阈值须标清。最差病例不得因为“看起来异常”就在结果阶段删除。

用于方案间并排比较的图必须展示同一批病例，并注明病例排序依据哪个方案。逐病例指标的种子平均不是一张预测掩码；展示轮廓时预先固定种子17，不事后选该病例表现最好的种子，也不把三个种子的概率平均后冒充单次模型结果。

## 9. 保存内容与完成条件

每次运行保存：配置副本及哈希、代码提交号、划分哈希、环境版本、训练种子、起止状态、训练曲线、最佳轮次、权重、验证阈值搜索表、预测概率、二值掩码及逐病例指标。建议记录字段如下，字段名是格式约定，不是实验数据：

```text
run_id, arm, seed, config_hash, split_hash, commit_id,
patient_id, image_id, split, threshold, tp, fp, fn, dice, iou,
precision, recall, pred_positive_fraction, evaluation_grid
```

自动检查12次运行是否齐全、各模型测试病例集合是否相同、阈值是否来自验证集、汇总能否从逐例表重新生成。训练失败要保留失败日志和重试理由，不能只保留每组最好一次。

论文应能够逐项对应：四组配置表、病例纳入与划分表、训练和验证曲线、12次运行结果、主要配对差异及区间、大小与边缘探索、正常图误检记录、失败叠加图。没有实际完成的部分标明“计划”或“待实验”，不给出推测的数值。

## 方法来源与结论边界

- [U-Net 原论文](https://arxiv.org/abs/1505.04597)：网络的编码器、解码器及跳跃连接基础。本文通道数、损失与超参数是本课题预设，不冒充原论文原样配置。
- [BrEaST 数据集论文](https://www.nature.com/articles/s41597-024-02984-z)：数据与标注定义。
- [TensorFlow 设置随机种子](https://www.tensorflow.org/api_docs/python/tf/keras/utils/set_random_seed)与[确定性计算](https://www.tensorflow.org/api_docs/python/tf/config/experimental/enable_op_determinism)：用于实现及解释可重复性的技术边界。
- [Apple TensorFlow Metal 说明](https://developer.apple.com/metal/tensorflow-plugin/)：用于核对本机安装与加速条件。

最终结论限定于该数据集及所采用的划分和训练方案。来源机构与采集条件的局限、小样本、静态图像、参考标注的不确定性及潜在图像标记依赖都需要讨论；研究未测量的临床用途不能由分割指标外推。
