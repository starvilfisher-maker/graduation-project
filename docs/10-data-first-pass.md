## 需要明确的通道编码

首次审计采用保守检查：只有不带透明信息且RGB完全一致的文件才直接提取灰度。因此多数病例被标记为`blocked`。这表示**读取规则尚未覆盖实际编码**，不表示病例医学上无效，更不是排除这些病例的依据。

后续全量只读编码检查发现：

- 256张原图中163张RGB通道并非完全相同，93张完全相同。初轮脚本遇到透明度就提前返回，因此初轮报告的135张颜色异常不是完整颜色计数。
- 31张原图存在透明像素；其中7张的透明区域还保留非零RGB。另有一张原图含5个部分透明像素。不能简单丢弃alpha而假定显示内容不变，也不能自动删除这些图像。
- 266张掩码RGB三通道相同，RGB值均为0或255。265张掩码的alpha与单个颜色通道逐像素相同，另一张掩码有2个部分透明像素。正式目标读取规则须明确依据哪个通道及如何处理例外。
- `other`与`tumor`仍分开处理。病例表指定的目标不能被文件数量或透明度规则改变。

这些检查描述的是像素存储，不评价医生轮廓的医学正确性。下一阶段需把已观察的编码约定转化成显式、可测试的读取规则，并生成全量叠加图核对。

## 现有脚本能做什么

运行入口为`scripts/audit_breast.py`，实现位于`src/breast_unet/data_audit.py`。依赖NumPy、Pillow、openpyxl；本次实际使用Python 3.12.14、NumPy 2.3.5、Pillow 12.3.0、openpyxl 3.1.5。这是本次审计环境记录，不是TensorFlow训练环境锁定。

项目的`audit`可选依赖组用于审计，在独立Python 3.10+环境中可通过`python -m pip install '.[audit]'`安装。版本下限只描述可安装范围，不等于所有组合都已验证；新环境应重新运行测试并记录实际版本。

```bash
python3 scripts/audit_breast.py --raw-dir data/raw/BrEaST-v1 --output-dir data/audit/my_first_audit
```

路径相对于项目根目录，输出目录必须不存在。输出`cases.csv`、`file_inventory.csv`和`audit_summary.json`。脚本不联网、不改原始文件、不生成划分、不合并多个tumor掩码、不训练。发现待处理问题后仍保存审计记录，退出码为2；执行成功且自动检查通过才返回0。

现有保守读取不接受实际透明掩码，所以首次审计没有完成全部掩码的前景面积和256×256最近邻缩放检查。列表中“未发现缩放消失”不能解释为“已经全部检查通过”，应同时看检查覆盖数。全量编码检查是辅助证据，尚未替代正式加载器验证。

最新运行目录为本地`data/audit/initial_20261014_v2/`；首轮`initial_20261014/`保留不覆盖。v2明确记录：266个掩码中有效目标解码检查0个、缩放检查0个。新增审计测试和既有指标测试共24项在本地全部通过，包含错误配对、缺失目标、alpha误用、尺寸差异、目标缩放消失、重复内容、空表及禁止覆盖输出等风险。

全部病例的`visual_review_status`仍为`pending_visual_review`，`training_ready`均为false。已制作并检查病例001的原图、目标掩码和参考轮廓三联示例；这不等于256例已完成逐例人工复核。
